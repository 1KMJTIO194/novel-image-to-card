# P0：世界观归并的两个结构修复

承接 `chapter-marker-formats.md` 的世界观审计。审计结论是**覆盖面没问题**
（原文出现 ≥3 次的概念全有对应条目），问题在**结构**：

1. 抽取器的防膨胀规则是**全局口径**，但抽取是**逐批**调用的
2. `mergeWorldbook` 的 key 是 `分类::名字`，**同名跨分类不去重**

两个修复都在归并层、不碰 prompt，用现有 21 章产出即可验证。

---

## 修复一：同名跨分类去重 —— 但只对「实体类」分类

### 问题

实测《示例小说 A》里 `御兽山` 被抽了两条：

```
[map_region]   御兽山  643 字  0 处「未提及」   ← 五峰十二谷、训兽管理、经济资源
[map_location] 御兽山  282 字  5 处「未提及」   ← 大量「原文未提及」
```

旧 key 是 `分类::名字`，两个分类不同 → **没被去重**，两条都进了卡，
而且低质那条跟高质那条在正文里**抢同一个触发词**。

### 关键：不能一刀切

我第一版实现是"所有同名跨分类都去重"，**归并测试立刻挂了**：

```
✗ 同名不同分类不合并 —— 1
```

而那条测试的注释写得很准：

> 同名不同分类不合并（体系层的"剑"与具体武器"剑"是两回事）

确实如此：`system_skill` 的「御剑术」是功法体系，`system_item` 的「御剑术」
可能是那本秘籍。**对它们做同名合并会丢信息。**

### 修法

只对**实体类**分类去重：

```js
export const ENTITY_CATEGORIES = new Set(
  ['map_world', 'map_region', 'map_location', 'system_faction']);
```

同一座「御兽山」不可能既是 A 区域又是 B 地点 —— 这种同名就是分类判断失误。
去重时保留**内容更长**的那条（实测正好是高质那条）。

## 修复二：分类上限全局生效，且**并入而非丢弃**

### 问题

上限写在 prompt 里：

```
规则（第 239 行）：map_world 和 system_realm 各最多 2 条
```

但抽取器逐批调用，实测每批各自占满上限：

```
batch_000  system_realm 1
batch_001  system_realm 2      ← 各自占满
batch_002  system_realm 2      ← 各自占满
────────────────────────
全局        5 条
```

### 第一版实现是错的

我第一版是"超出上限就保留最长的 N 条、其余丢弃"。跑真实数据后发现：

```
被丢弃: [system_realm] 炼心路  519 字  (over-cap)
```

**「炼心路」是独立设定** —— 走通它才能"自主筑基"，走不通只能靠筑基丹补救。
它跟"境界/灵根"完全不是一回事。按"保留最长的 2 条"裁掉它，
就是实打实的信息损失。

### 修法：并入，不丢弃

```
超出上限的条目 → 把它的独有内容并入**同分类保留者**的正文
                 （按 keys 命中选择最相关的保留者）
```

并入时加来源标记，keys 也合并：

```
【补充·炼心路】
原文未提及炼心路的具体分段或关卡构成，只知其是修士在筑基之前
所要走过的一条历练之路，与「自主筑基」直接绑定。…
```

实测结果：

```
system_realm 保留 2 条：
  修炼境界与灵根体系  695 → 2315 字   keys 从 5 个 → 15 个
  修为境界（炼气期·筑基·元婴）  593 字
```

三条被并入（`修行境界体系` 569 字 / `炼心路` 519 字 / `灵根资质体系` 493 字），
**内容一条没丢**。

### 附带好处

合并后 `system_realm` 条目变大（2315 字），而 A 包预算裁剪会把
`system_realm` 降级为按键触发（A 包由 map_world + timeline + synopsis 占满），
所以**大条目不再压常驻预算**：

```
A 包常驻 3 条 / 1769 tok（上限 2000）
  540 tok  [timeline]
  792 tok  [synopsis]
  439 tok  [map_world] 修真界
```

## 端到端验证（重跑同一本小说，真实模型）

重跑后模型这次把 `system_realm` 抽成 4 条（每批 1-2 条），裁剪按预期生效：

```
[Step 2.5] 归并：… 世界观 46 → 38
merge_report.worldbook:
  inputCount: 46
  afterSameCategory: 40
  crossCategoryDropped: [
    { name: 修真境界与灵根, category: system_realm, reason: over-cap-merged-into, mergedInto: 修仙境界体系 }
    { name: 炼心路,         category: system_realm, reason: over-cap-merged-into, mergedInto: 修炼境界与灵根 }
  ]

system_realm 最终 2 条：
  修炼境界与灵根   592 → 1250 字  keys 9 个   （含【补充·炼心路】485 字）
  修仙境界体系     753 → 1345 字  keys 8 个   （含【补充·修真境界与灵根】592 字）

同名多分类：[]（空）
```

`御兽山` 这次没被抽成两个分类，所以那条路径未被触发 —— 单独注入一个低质副本验证过：

```
注入后：御兽山只保留 [map_region] 692 字
账本：{ name: 御兽山, category: map_location, chars: 20, reason: same-name-other-category }
```

最终指标：`A 包 1811 tok`（限内）/ `B 包 3576 tok`（仍超 76）/ 45 次调用 0 失败。

## 两个 API 变更

```js
// merge_batches.js
mergeWorldbook(itemsPerBatch, { categoryCaps = WORLDVIEW_CATEGORY_CAPS })

// 返回的 report 多了两个字段（原字段不变，向后兼容）
report.afterSameCategory        // 同名同分类合并后的条目数
report.crossCategoryDropped     // 处置明细：reason 为
                                //   same-name-other-category（同名跨分类，丢弃低质那条）
                                //   over-cap-merged-into（超上限，已并入 mergedInto）
```

⚠️ `report.dropped` 是**条目数**的减少，不是内容丢失 ——
`over-cap-merged-into` 那些条目的内容都在保留者正文里。

## 测试

`tests/merge_batches.mjs` 60 → **68**，新增 8 条：

**实体类同名去重**（3 条）
- 实体类同名跨分类去重
- 保留信息更全的那条
- 跨分类去重有账本

**分类上限全局生效**（5 条）
- `system_realm` ≤ 2
- 超限条目的**独有内容被并入**（不丢弃）
- 并入时带来源标记 `【补充·…】`
- 账本标明 `mergedInto`
- 并入后 keys 也合并

同时**保留**原有那条「同名不同分类不合并」——
它是"不能一刀切"的证明，不能删。

全量 **24 套件 / 2305 断言全绿**。
