# 章节标记格式：第二本真实小说跑出来的 bug

第二本小说（《示例小说 A》，139,315 字节 / 47,743 字 / 938 行）用的是
**`☆、001` 到 `☆、021`** 这种章节标记，而不是 `第N章`。
旧实现只认识 `第N章`，于是：

```
整篇 47,743 字只切出 1 处"章节"
—— 而且那 1 处还是误命中：正文对话里的「可是第一回到求道谷的？」
21 章的真实结构全部丢失
```

连锁后果和之前一样（章序全错、分批失效、提及塌陷），但因为整本被当成一章，
后果更严重：所有事件都被归到同一个"章"下。

## 为什么之前的实现会误命中正文

```js
// 旧实现
const re = /(?=第[一二三四五六七八九十百千零两\d]+[章回节])/;
let parts = String(text).split(re);
```

这个 lookahead **允许标记出现在任意位置**，所以正文句子里的「第一回」
也会被当成章节分隔。它本来是为了兼容"整篇挤一行"的文件（那种文本里
章节号夹在正文之间），但代价是误命中率高。

## 修法：行首标记优先，行内匹配退回

```
① 逐行扫描：行长 ≤ 80 且行首是章节标记 → 真实章节（严格路径）
② 一个都找不到 → 退回行内匹配（宽松路径，兼容单行文件）
```

严格路径的标记正则覆盖这些实测格式：

| 格式 | 例子 |
| --- | --- |
| 星号 + 顿号 | `☆、001` / `☆.001` / `☆001` |
| 中文章节 | `第1章 标题` / `第十二回` / `第3节` |
| 纯编号单独成行 | `001.` / `1、` |

## 一路上踩到的 5 个坑

这些都是"改了之后换个测试才发现"的，记下来免得再犯。

### 1. 标记行必须限长

"整篇挤一行"的文件里，那一整行是几百上千字的正文，而它天然**以行首开头**、
也可能**一个句号都没有** —— 会被判成"章节标记行"。

后果很严重：前言无限叠加，产出 **6000 万字**的块（测试断言 `63538347 vs 19218` 抓到的）。

修法：`MARKER_LINE_MAX = 80`，超过就不当标记行。

### 2. `String.split` 会把每个捕获组插进结果

原来用 `src.split(RE)` 切分，而 `RE` 里有一个捕获组 `(第N章)`。
`split` 的规则是"结果数组里**插入每个捕获组**"，于是：

```js
"…正文第17章，心照不宣…".split(/(第17章)/)
// → ["…正文", "第17章", "，心照不宣…"]      ← 标记和标题被切开了
```

标题因此只剩 `第17章`，甚至退化成一个孤零零的「，」。

**修法：改用 index 切分**（`matchAll` 取 `index` 再 `slice`）。
不要试图靠调整捕获组解决 —— 我曾经写成 `(第N章[^\n]{0,24})` 想把标题一起捕获，
结果它反过来吃掉了标记**前面**的正文，切出来的段落变成
`第16章荒唐的赌约，妈要嫁人…`（前半截是上一章的正文字），标题更乱。

### 3. `\r` 让所有正则的 `$` 锚点失配

CRLF 文件按 `\n` 切分后每行残留 `\r`，而 `☆、001\r`：

- 不匹配以 `\d{1,4}\s*[、.．·]\s*$` 结尾的分支（`\r` 不是 `\s` 里的成员？）——
  实际会走"纯编号单独成行"那条，**捕获组只拿到 `☆、`**，标题全变成 `☆、`
- `looksLikeBookTitle` 里的 `CHAPTER_LINE_RE.test(s)` 同样失配

修法：加 `stripCR()`，并在**每一处**用之前先剥掉。
漏掉一处（`introSentence` 里）就复现了 `☆、` 这个 bug。

### 4. 顿号 `、` 在句读集合里，会把标记切碎

`SENTENCE_END` 含 `、`，而 `☆、001` 的顿号在**第 2 个字符**上。
`firstSentence("☆、001")` 在顿号处收口，返回 `☆、`。
所以章节标记行必须**整行返回**，不能过 `firstSentence`。

### 5. 书籍元信息行会被当成"第一句正文"

`书名：示例小说 A` / `作者：示例作者` 带**冒号**，而冒号在句读集合里 ——
于是不会被"无句读"那条判据拦住，反被当成"本章第一句正文"取作前言，
续块标题就变成 `【2/2】书名：`。

修法：加 `BOOK_META_RE`（`书名/作者/简介/标签/…`）判据。

## 顺便修好的：正文句子里的「第一回」

严格路径锚定行首之后，还剩一个单行文本的情形。判据是**结构性**的：

```
第一回到求道谷的？      ← 「第一回」后面紧跟续接虚词「到」→ 句中成分
第一回 入山            ← 后面跟标题 → 章节标记
第一段第16章荒唐的赌约   ← 后面不是虚词 → 章节标记
```

`/第\s*[…\d]+\s*[章回节](?![到了过之]|的)/`

加这条否定前瞻后，**单行**文本里的对话误命中也被排除了
（原来只能切出 2 章，现在是正确的 1 章）。

## 顺带发现：A 包常驻超预算 75%

跑完整抽取后发现 `A 包常驻 3510 tok / 上限 2000` —— **超了 75%**。
A 包是每轮都注入的固定开销，超支不会被任何人发现（只多一行日志）。

拆开看常驻条目：

```
753 tok  [synopsis]      原著剧情简介
584 tok  [map_world]     启元大陆
568 tok  [timeline]
484 tok  [system_realm]  修仙境界体系
484 tok  [system_realm]  修行境界与灵根体系
426 tok  [system_realm]  灵根资质
409 tok  [system_realm]  修仙境界与灵根资质
---- 合计 3708 tok（上限 2000）
```

**4 条 `system_realm` 其实是同一套体系的不同说法**，合计 1803 tok，占 A 包的 49%。

原因：`category === 'system_realm'` 被**整类**判成常驻，而抽取是逐批做的，
同一类会产出多条语义重叠的条目。而 `validate()` 只 `warnings.push`，**不做裁剪**。

### 修法：两步裁剪，内容不丢

```
第一步（始终执行）：同类只留第一条常驻
        —— 4 条 system_realm 都每轮注入本身就是错的，跟总预算够不够无关
第二步（仅超预算）：从后往前继续降级，保住 map_world / timeline / synopsis
```

降级**不丢内容**：条目仍在，只是从"每轮都注入"改成"按 keys 触发"。
实测被降级的 4 条 keys 都有实际内容（`炼气期`/`筑基`/`灵根`/`资质`…），
所以相关正文出现时照样会注入。

效果：**7 条 3513 tok → 3 条 1825 tok（限内）**。

这一步也暴露了一个**更上游的问题**：`mergeWorldbook` 只按"分类 + 名字"去重，
不认语义相似 —— 所以四条同义条目能同时存在。裁剪只是**兜住预算**，
真正的解法是在归并阶段做一次语义去重（未做，需要单独验证）。

## 未修：B 包也超预算（同一类"只警告不裁剪"）

A 包修好后重跑，`A 包 1771 tok / 上限 2000`（限内），但 **`B 包 3768 tok / 上限 3500`（超 268 tok）**。
B 包同样只有警告、没有裁剪。

拆开看，`b1_variables` **一个键就占 3076 tok**，占 B 包的 82%：

| 段 | token | 行数 |
| --- | --- | --- |
| `events` 段 | 2703 | 254 |
| `characters` 段 | 287 | 39 |

原因很清楚：**每个事件用 5 行固定缩进展开** `status` / `deviation` / `pressure`：

```yaml
events:
  叶诺重伤返坊市:
    status: ongoing
    deviation: 0
    pressure: core
```

63 个事件 → 254 行。而 `b2_update_rules` 只要求 AI 更新 `status` 与 `deviation`，
`pressure` 是给生成器用的元数据（分层/导演指令），**不需要每轮都呈现**。

### 可行的压缩方案（未实施）

改成 YAML **flow 风格**展平到一行，同时保留可解析性（酒馆助手要 replace 它）：

```yaml
events:
  叶诺重伤返坊市: {status: ongoing, deviation: 0, pressure: core}
```

预期 63 × 43 = 约 2709 字符 ≈ **1690 tok，省 1000 多 tok**。

**为什么没做**：`b1_variables` 是"当前变量树"的呈现，模型要按它输出 `_.set(...)`。
改格式等于改变模型看到的输入结构 —— 必须用真实模型跑一遍确认它仍能正确产出 replace 语句，
否则会把"B 包缩小"换成"变量更新失败"。这属于**需要单独验证的改动**。

## 测试

`tests/chapter-range.mjs` 50 → **65**，新增一节【8】：

- 8 种真实章节格式逐个断言（星号 3 种写法、第N章 2 种、中文数字、回目、纯编号）
- `☆、001` 的标题必须完整（不被顿号截断成 `☆、`）
- 整篇挤一行时：块数正常、每块不超限、前言叠加可控
- 段落中间的对话「第一回」不算章节标记
- 单行文本里的行内「第一回」也不算，但**真正的行内开新章仍能识别**

`tests/robustness.mjs` 63 → **68**，新增 A 包预算裁剪的 5 条断言：

- 同类常驻只留一条（`system_realm`）
- 常驻总量被裁到预算内（≤ 2000 tok）
- 裁剪保留世界概览 / 时间线 / 简介
- 降级的条目仍带 keys（内容不丢）
- 内容条数不因裁剪而减少

全量 **24 套件 / 2297 断言全绿**。

## 一点方法论

这一轮 5 个坑里有 4 个是**测试数据没覆盖到的格式差异**造成的，
而且每次都是"修好一个、另一个测试挂掉"才暴露：

- 加行首锚定 → 破坏单行文件支持
- 给标记行加长度上限 → 修好无限叠加
- 改用 index 切分 → 修好标题截断
- 加 `\r` 剥离 → 修掉 `☆、`

所以这轮的价值不在"支持了星号格式"，而在**把章节切分的行为在测试里钉死**
（8 种格式 × 3 档长度 × 唯一性 + 3 个反向用例）。
