# 状态栏时间与事件触发词

两处用户反馈的修复，根因都在"只拿到原文片段，没有做解析"。

## 一、状态栏时间没有几月几日

### 现象

状态栏显示 `1960年`，但用户要的是 `1960年12月25日` 这种。

### 根因

`world.time` 直接取**时间线首条的原文片段**，而首条常常只有年份：

```
真实产物 task_1790294538471 的时间线（前几条）：
  1960年                 当前年份        ← world.time 取的是这条
  10月9日                《哈利波特》出版一星期
  1960年12月25日          《哈利波特与密室》发布
  6月1日                 《阿兹卡班的囚徒》发售
```

三个问题叠在一起：

1. **首条最不具体**：首条是 `1960年`，真正有月日的条目在后面；
2. **裸月日没有年份**：`10月9日`、`6月1日` 挂在哪儿一年，原文没写、代码也没推；
3. **显示的是原文片段**：`现在是1961年`、`整个二月，甚至三月` 这种会被原样搬进状态栏。

### 修法

新增 `src/dates.js`：从原文片段解析出年/月/日。

- `parseDateParts` 支持 `1960年12月25日` / `10月9日` / `六十年代` / `天启三年春` /
  一九六一年四月八日 / `12月25号` 等写法
- `resolveDateYears` 给缺年份的补年份 —— **只在有明确依据时**：
  用"它前面最近的、带年份的条目"。补不出就留空，绝不默认成某一年
- **只在原文里真的写了月日时才有月日**。原作用"天启三年春"这种季候写法时，
  我们不会凭空造一个"3月1日" —— 那会伪造原文没有的信息

时间线顺序也顺手修了：`pickWorldDate` 现在按"最可信且最具体"挑起始时间。

### 两个排序陷阱（都实测踩过）

**陷阱 1：推断年份盖过明确年份。**
`1960年10月9日` 的年份是按上文推的，而 `1961年的4月8日` 是原文明确写的 ——
如果只按"精度优先"，会选前者，于是状态栏显示一个**错的年份**。
显示错年份比显示不出月日严重得多（AI 会在错误的年代里推进剧情）。

**陷阱 2：反过来也不能一刀切。**
如果推断出来的年份**与明确年份相同**（都是 1961），那"明确"没带来任何新信息，
此时应当让更精细的那条赢（`1961年4月8日` > `1961年`）。
一刀切"明确优先"会为了一个没差别的标签丢掉月日。

最终口径（顺序不能动）：

```
1. 明确年份 vs 推断年份，且年份值不同 → 明确的接管
2. 年份都明确（或都不可比）→ 精度高的优先：有月日 > 有月 > 只有年
3. 仍然相同 → 取日期更早的
4. 还分不出 → 保留时间线里先出现的（叙事顺序）
```

### 产物变化

```jsonc
// variables.json
{
  "world": {
    "time": "现在是1961年",              // 保留原文片段，向后兼容
    "date": {                            // 新增：状态栏读它
      "text": "1961年4月8日",
      "year": 1961, "month": 4, "day": 8,
      "precision": "day",
      "inferred": false                  // 年份是不是推出来的
    }
  }
}
```

状态栏三套模板（protagonist / participant / observer）都改成读
`stat_data.world.date.text`，取不到才回退 `world.time`。
精度只到年时，模板会额外给一句提示，让 AI 在剧情里出现"几月"时去补 `world.date`。

B2 的变量更新规则也加了 `stat_data.world.date`，AI 每轮会顺带维护它。

## 二、事件触发词太少，剧情大量漏触发

### 现象

4 个事件，触发词合计 4 个 —— **每个事件只有 1 个 key，就是事件名本身**：

```
keys=[邀莉莉拍电影]      [event] 邀莉莉拍电影
keys=[密室签售会]        [event] 密室签售会
keys=[丽莎量体定制内衣]   [event] 丽莎量体定制内衣
keys=[制作GameTV]        [event] 制作GameTV
```

而事件名是抽取器**造的概括短语**，正文对话里几乎不会原样出现。
世界书是 key 触发，于是不刻意引导就基本不会加载 —— 剧情大段错过。

（顺带发现：事件条目正文里 `时间：（未定）` —— 时间回填没覆盖到不含章节标记的事件。
这是另一个既有问题，本次未动。）

### 修法

事件抽取新增两个字段（模型本来就知道，只是没让它输出）：

```jsonc
{
  "name": "邀莉莉拍电影",
  "participants": ["除主角外，参与本事件的人物名"],
  "location": "原文中真的出现过的专有地名"
}
```

`deriveEventKeys` 据此派生多组触发词：

| 来源 | 例子 | 作用 |
| --- | --- | --- |
| 事件名（原样保留） | `邀莉莉拍电影` | 显式提到事件时 |
| **解析出的日期** | `1960年12月25日` | 叙事写到日期时 —— 最能"自然触发"的一类 |
| **在场人物** | `莉莉` | 对话提到某人时 |
| **地点** | `电影社活动室` | 走进/提到某地时 |

实测（e2e）：

```
开篇入城 → ["开篇入城", "3月12日", "沈砚", "云京城门"]
初见沈砚 → ["初见沈砚", "沈砚", "城南茶楼"]
夜探旧宅 → ["夜探旧宅", "沈砚", "旧宅"]
```

### 风险控制（宁可少触发，也不要误触发）

误触发的代价比漏触发更高：世界书被塞满、上下文预算被吃光、
AI 在错误的时机读到错误的剧情。所以：

- **排除主角名**。主角几乎每轮都在场，拿它当 key 会让**所有事件常驻**。
- **日期必须到"日"**。只用月份（`6月`）会让整个月里每轮对话都触发。
- 单字名不用（歧义太大，命中率过高）。
- 泛指地点不用（`城里` `街上` `屋里` 这类写死的黑名单）。
- 总数封顶 6 个，超出按上面的优先级截断。
- 全部去重。

## 三、顺带修掉的两个 bug

**① `十二月` 被解析成 2 月。**
中文月份正则原来用 `{1,3}` 量词，它会**回溯**，在「十二月二十五日」里只吃到「十」——
而 10 是合法月份，于是静默得出 2 月。改成贪婪匹配整串数字后交给 `cnNumToInt`。

**② `Date.UTC(1961, 14, 1)` 会静默滚到 1962 年 3 月。**
非法月份/日期不报错，而是滚到下一个月/年，产出一个看着合法、实际错误的日期。
`addDays` 与 `parseDateParts` 现在都做范围校验，越界一律"解析不出"而不是硬算。

## 六、按天打包（后续追加）

用户诉求：「有些剧情在一天内是连续的话就直接将那一天的内发生的剧情打包，不要拆分」。

### 先说一个我举错的例子

上一轮我用「凯瑟琳生日 = `1961年的4月8日`」和「阿兹卡班的徒发售 = `6月1日`」当"同一天被拆开"的例子。
**那个例子是错的。** 查原始提及后：

```
凯瑟琳生日           6月1日        quote: 凯瑟琳的生日也在6月1日
《阿兹卡班的徒》发售     6月1日        quote: 6月1日是《阿兹卡班的徒》发售
拜访珍妮家           1961年的4月8日  quote: 时间到了1961年的4月8日
《女巫布莱尔》上映       7月份         quote: 7月份…也会上映
```

同一天的是**生日与发售**（都在 6月1日），不是生日与拜访。源文本没问题，是我张冠李戴。

### 但真正的问题被这个错误暴露出来了

`backfillEventTimes` 原来是**每章只取最早出现的那个时间点**：

```js
for (const e of tl) {
  if (!e.chapter || byChapter.has(e.chapter)) continue;   // ← 每章只留第一个
  byChapter.set(e.chapter, e.time);
}
```

于是同一章里的 `6月1日`、`7月份`、`1961年的4月8日` 全被压成 `6月1日` ——
事件之间毫无区分，也根本没法按天打包。这就是"一天内的剧情被拆散/糊在一起"的机制。

### 修法

**1. 时间线条目解析成完整日期**（`resolveTimelineDates`），并带上 `dateKey`。

**2. 事件与时间点按优先级对齐**（重写 `backfillEventTimes`）：

```
1. 事件名与时间线条目名相同 / 互相包含
2. 同一章内，事件名出现在该条目的 quote 里
3. 同一章内，事件名与该条目名有公共词（≥2 字）
4. 同一章内，按叙事顺序把还没被占用的条目依次分给各事件
5. 都没有 → 故事起点时间兜底
```

**3. 按天分组**（`groupEventsByDay`）：

- 有 `dateKey`（解析到具体年月日）→ 同一天合成一条
- **没有 `dateKey` 的各自独立成条**，绝不硬凑到某一天（凑错会把无关剧情并到一起）

**4. 两条组装路径共用**同一套打包逻辑，保证 A 包与完整卡长得一样。

### 实测效果

```
[event] 1961年6月1日（2 个事件）         ← 同一天，打包成一条
  keys: [凯瑟琳生日会, 阿兹卡班发售, 1961年6月1日, 6月1日, 莉莉, 公寓, 书店]

[event] 拜访珍妮家                       ← 4月8日，另一天，独立成条
  keys: [拜访珍妮家, 1961年4月8日]

[event] 女巫布莱尔上映                    ← 只有"7月份"，解析不到具体某天 → 独立
  keys: [女巫布莱尔上映, 影院]
```

打包条目的触发词是**组内并集**，所以提到当天任何一个人、地点或日期
都能把这天的剧情整包加载 —— 这正是"不要拆分"想要的效果。

正文里逐个事件保留完整信息（时间/原著/压力/在场/地点/干预分支），**打包不丢信息**。

### 顺带修正：跨章借年份会编出错误日期

日期解析一开始"沿用最近一个有年份的锚点"，会**跨章节**借用。实测：

```
第二十五章：现在是1961年
第二十六章：6月1日（生日/发售）、1961年的4月8日（拜访）
```

第 26 章的 `6月1日` 被补成 `1960年6月1日` —— 而同一章里有显式的 `4月8日`，
两者自相矛盾。更糟的是这个错年份会进状态栏。

改成**章节内锚定**（`resolveDateYears` 的 `window: 'chapter'`）：
拿不准就留空年份，显示 `6月1日` 而不是一个可能错的年份。
按天分组不受影响（`dateKey` 只需要月日）。

## 附二：未能验证的

- **月日的真实性**：状态栏显示到日的前提是**原文里真的写了月日**。
  原作用"天启三年春"这种季候写法时不会显示月日 —— 此时不会伪造，
  而是显示 `春季` 并给 AI 一句提示。
- **触发词的实际触发效果**：沙箱里没有真实 SillyTavern，
  只验证了 keys 生成正确。真实使用中若发现某个事件被过度触发，
  可以调 `deriveEventKeys` 的 `max` 或去掉某类来源。
- **推断年份的正确率**：`inferred: true` 的年份是按上下文推的，
  原作时间线有跳跃（倒叙、回忆）时可能推错。状态栏会标注"（年份按上下文推断）"，
  让用户能判断要不要手动改。
- **按天打包的取舍**：同一天合成一条后，这一天的事件在世界的面板里
  **无法单独启用/禁用**（要么整包加载、要么整包关掉）。
  这是"不要拆分"的必然代价；现在靠"只有解析到具体某天才打包"来限制影响面 ——
  没日期的剧情仍然是一条一个事件。
